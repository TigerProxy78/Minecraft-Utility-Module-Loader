# Minecraft‑Utility‑Module‑Loader  

**Author:** *TigerProxy78*  

A lightweight, plug‑and‑play loader that lets you configure, load, and manage custom Minecraft modules without touching the core game files. Perfect for modders, server admins, and anyone who wants a clean, modular workflow.

## 📚 What Makes This Loader Different?  

| Feature | Why It Matters |
|---|---|
| **Zero‑Code Configuration** | All settings live in a human‑readable JSON file – no Java code required. |
| **Hot‑Swap Modules** | Add, remove, or update modules while the game is running (with a simple reload command). |
| **Dependency Graph** | Automatic resolution of module load order; circular dependencies are flagged early. |
| **Sandboxed Execution** | Modules run in an isolated classloader, protecting the base game from crashes. |
| **Cross‑Platform** | Works on Windows, macOS, and Linux – only a JRE 17+ is needed. |

## 🧩 Modules  

Modules are simple JAR files that expose a `module.json` descriptor. Example layout:

```
modules/
├─ example‑weather‑enhancer/
│  ├─ example‑weather‑enhancer.jar
│  └─ module.json
└─ custom‑biomes/
   ├─ custom‑biomes.jar
   └─ module.json
```

### `module.json` template  

```json
{
  "id": "example-weather-enhancer",
  "name": "Weather Enhancer",
  "version": "1.2.3",
  "description": "Adds dynamic storms and visual effects.",
  "entrypoint": "com.example.weather.WeatherMod",
  "dependencies": {
    "minecraft": ">=1.20",
    "other-utility": ">=2.0.0"
  }
}
```

Place the JSON file **next to** the JAR; the loader will read it automatically.

## ⚙️ Configuration  

The main configuration lives in `loader-config.json` (generated by the Release wizard). Key sections:

```json
{
  "loader": {
    "debug": true,
    "logLevel": "INFO"
  },
  "modules": {
    "enabled": [
      "example-weather-enhancer",
      "custom-biomes"
    ],
    "disabled": [
      "experimental‑features"
    ]
  },
  "paths": {
    "modulesDir": "modules",
    "tempDir": "temp"
  }
}
```

- **debug** – prints verbose logs to the console.  
- **logLevel** – `TRACE | DEBUG | INFO | WARN | ERROR`.  
- **enabled/disabled** – whitelist/blacklist for module activation.  

Edit the file manually or use the built‑in `/loader config` command inside Minecraft.

### Running the Project Locally  

```bash
# Clone the repo
git clone https://github.com/yourusername/Minecraft-Utility-Module-Loader.git
cd Minecraft-Utility-Module-Loader

# Build
./gradlew clean build

# Execute the loader (replace <path-to-minecraft> with your game folder)
java -jar build/libs/mum-loader.jar --minecraft <path-to-minecraft>
```
